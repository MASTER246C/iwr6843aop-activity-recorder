# Verification record

## 0.3.3-dev source (unreleased)

Status: host-tested only. This source has **not** been built with the TI toolchain, **not** flashed and **not** physically tested. No 0.3.3-dev BIN, ELF or receipt exists. The 0.3.2-rc1 candidate below remains the binary the matching viewer accepts, and the rollback chain is unchanged. The new build ID `cfb33b51d6b855e7b93b52dc` in `BUILD_IDENTITY.json` identifies source/config only.

`bash tests/run_tests.sh` passed on a Linux x86-64 host with gcc 13.3.0 (`-Werror`, AddressSanitizer and UBSan) and Python 3.13. It writes only to `build/host-tests/`. Each new or changed check failed against the unmodified 0.3.2-rc1 source or tool before its fix:

- `tests/test_radio.c` compiles the real `src/radio.c` against host fakes in `tests/stubs/`. A rejected `MMWave_stop` (or a missing frame end) must leave RF started and open with no `MMWave_close`; the next stop must retry and close only after the frame end. The success and warning paths must stay unchanged. The 0.3.2-rc1 `radio.c` closed RF after the rejected stop.
- `tests/test_boot_gate.py` adds first-cause cases. A lease expiry (463) must survive a failed RF stop (403), and a data-transport fault (484) must survive the revoked lease (463), a failed RF stop and a busy DSP (402). A `stop` in fault state must reach the RF stop again. The 0.3.2-rc1 `main.c` reported 403 and 463 instead.
- `tests/test_tool_checks.py` runs `tools/verify_sensing.py` and the `tools/package_firmware.sh` CRC check under `python -O` on synthetic bad ELF/map/image bytes. Under `-O` the 0.3.2-rc1 tools printed `offline_checks_passed` for a map containing a forbidden demo symbol, and `Independent CRC32 check passed` for a corrupted CRC.
- `tests/test_sensing.c` now covers the true serialized worst case for the firmware path: a known signed offset, three valid sensor_xyz estimates, maximum-width numbers and maximum counters. It is **1709 bytes**, within the 1800-byte cap. With the cap lowered to 1700 bytes, the earlier 1625-byte case still passed and the new case failed. `src/json_output.c` is unchanged from 0.3.2-rc1, so the 1709-byte bound also describes that candidate's serializer. world_xyz stays null because firmware never asserts phase/axis calibration. A synthetic check with both flags forced measured 1804 bytes, so enabling calibration later would first need a cap/serializer review.
- `tests/test_acquisition.c` gives `src/acquisition.c` its first host coverage, against the same fakes. It checks ping/pong EDMA parameter/link wiring, completion/take/release ownership, overrun, partial-frame, wrong-slot and EDMA-error fault codes, timestamps across the tick rollover and beyond 32-bit microseconds, and stop/re-arm. Mutations of the slot wiring, EDMA close, fault latch and 64-bit timestamp were detected. It disables only the unknown-pragma and 32-bit pointer-cast warnings that the target-only source needs.
- `make clean` was run in a throwaway copy of the tree, with and without `BUILD=build/0.3.2-rc1`. All 194 tracked firmware files survived, and the receipted folder was refused. The 0.3.2-rc1 Makefile deleted all four tracked `build/` artifacts. The compiler-revision guard was exercised only with fake `armcl` scripts; it is unverified on a real TI host, including the XDCtools Windows shell.

The host fakes are original declarations written from the call sites; they are not TI headers and say nothing about TI driver behavior, interrupt timing or DMA. Fault-precedence and stop-retry behavior on target hardware, under RTOS preemption, remain unvalidated. One known limit: the first-cause latch is a plain check-then-store, not an atomic operation across tasks.

## 0.3.2-rc1 candidate (unchanged binary)

Status at build time: built and tested offline; physical acceptance pending. No board, serial device, flasher, deployment or publication was accessed.

Later hardware run: the candidate ran on one owner-run IWR6843AOPEVM on 2026-10-12. The [first combined run](../../docs/FIRST_COMBINED_RUN_2026-10-12.md) records matching pairing, 283 complete consecutive 5 Hz frames over 56.4 seconds with zero reported faults, 53 keepalive ACKs and a manual Stop to fault-free idle. It was a brief acquisition/Stop test reviewed by the development agent, not independent laboratory validation. Deliberate keepalive-loss/disconnect Stop, endurance, timestamp rollover, calibration, position and activity accuracy remain untested. The receipt below is an unmodified build-time record, so its `PENDING` acceptance field predates that run.

The actual candidate receipt is `build/0.3.2-rc1/BUILD_RECEIPT.json`. Build ID: `87589b2c32638ae119334c72`. Candidate BIN:346,436 bytes, SHA-256 `162db11aa7472d939b1039557bcad95253752c6562261d5ed851d6216c574fb9`, appended CRC32 `0xd2704b46`. Debug ELF SHA-256: `2b08810c8f9b9c31d9f81039c334d269cc468f63d63894641fc295d622647ff6` (local audit artifact).

Official native Windows TI ARM CGT 16.9.6.LTS compiled and linked against SDK 03.06.02.00-LTS, SYS/BIOS 6.73.01.01 and XDCtools 3.50.08.24 with warnings treated as errors. Official Windows ImageCreator tools packaged the BIN. Independent CRC32, exact MSS RPRC inclusion, embedded version/build identity, source identity and structural ELF/memory/driver-symbol checks passed. A repeat official packaging run produced byte-identical BIN output.

The SDK CRC tool printed `Failed to remove CRC temp file` and returned 0 in both packaging runs. This warning is preserved in the receipt; independent output checks passed. Converters now run in a disposable temporary working directory, so the SDK's temporary crcFile does not remain in the source tree. Successful packaging does not establish board behavior.

Zig 0.15.2 host C tests passed with strict warnings and effective undefined-behavior checks; a deliberate signed-overflow probe trapped. AddressSanitizer is unavailable: an address-only probe could not link the required __asan_* runtime. Combined address/undefined flag acceptance must not be called ASan proof.

Behavioral checks passed for bounded/continuous configuration; capture ownership and 64-bit time extension across raw-clock wrap; DSP 706 checks; spatial 1874 cases; boot self-test; UART record transport; tuple/rolling-lease/revocation/exhaustion; and 3228 synthetic AOP cases. The actual-main mocked harness sustains a 72-minute synthetic continuous run with keepalives, then verifies expiry Stop, rejected wrong/stale tuples, manual Stop and pairing-revocation Stop while retaining the inherited no-RF/self-test/fault gates. These are simulated time and mocked peripherals, not wall-clock radar operation. All 13 historical v1 collector tests pass; that collector does not control this v2 firmware.

An exact-source dual-UART framing model independently parses 1000 sessions,5000 control records (including tuple-bearing keepalive ACKs) and 2000 data records on separate simulated lanes. Maximum tested numeric frame serialization is 1625 bytes within the 1800 byte cap. That case had no valid sensor coordinates or known offset; the true worst case for the same serializer is 1709 bytes (see above). No physical peripheral behavior is implied.

The accepted prior 0.3.1 BIN SHA-256 remains `668476d4130f659cef4c1fea3b8eb436d5025f20853dc30ca83380f9bd38a6bf`; its root RELEASE_MANIFEST is unchanged. Prior documentation/identity is preserved under HISTORY/v0.3.1-rc1. Current candidate files have a separate manifest. No 0.3.1 artifact has been relabeled.

Physical boot, UART routing/baud/framing, RF and EDMA operation, target processing deadlines, stack headroom, temperature/endurance, geometry and tracking remain unvalidated. This new build has not been executed in target instruction emulation. RTOS or callback stalls still prevent a hard wall-clock Stop guarantee. Exact identity/self-test/no-RF pairing, manual Stop and heartbeat-loss Stop require board acceptance before a supervised continuous sensing run. No human count, posture classifier, camera labeling or radar ML acceptance is claimed. This paragraph states the build-time position.
